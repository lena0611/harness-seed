## 검증 CI 거취 — 다음에 다룰 것 (2026-09-11 사용자 지시로 이월)

**사실관계는 다 모았습니다. 판단만 남았습니다.**

- **개발자는 macOS 와 Windows 뿐입니다**(사용자 확인). Windows 는 Git Bash 라 `sh` 가 bash입니다 — **우분투 러너는 아무도 대표하지 않습니다.**
- CI 가 지금까지 잡은 것은 두 건이고 **둘 다 소비자 영향 0건**이었습니다. 0.2.136 러너 git 신원(CHANGELOG 에 "소비자 영향 없음(테스트 인프라)" 명시), 0.2.150 dash/pipefail(훅은 멀쩡, 테스트만 잘못된 셸로 호출). 즉 "하네스가 리눅스에서 깨진다"가 아니라 **"테스트가 리눅스에서 안 돈다"** 였습니다.
- 제품이 스스로 bash 훅을 `sh` 로 부르는 곳은 없습니다(확인함). `sh` 로 부르는 건 `.githooks/*`(진짜 POSIX sh)뿐입니다.
- **남는 값은 하나**: 새로 clone + `npm install` 한 상태로 도는 검증(로컬 찌꺼기 덕에 통과하는 것을 잡음). OS 와 무관하므로 맥 러너로도 됩니다.
- **구조 위험 둘**: ① 회사 표준 저장소의 **유일한 코드 검증 CI 가 개인 GitHub 계정**(`github.com/lena0611`)에 매달려 있습니다. GitLab 쪽 `.gitlab-ci.yml` 은 공지 발송 잡 하나뿐입니다. ② **결과가 사람에게 닿는 경로가 없습니다** — 6번 연속 빨강을 아무도 못 봤고, 0.2.136 때 같은 일이 있었는데 9일 뒤 재발했습니다.
- 선택지: **A** CI 제거(pre-push 가 이미 같은 279종을 진짜 환경에서 돌림) · **B** 러너만 macOS 로(새 clone 값 유지, 맥 러너는 과금 10배) · **C** 유지.
- 결정 113 에 배경이 있습니다. **체크리스트에 한 줄 더 적는 방식은 이미 두 번 실패했습니다** — 알림 경로를 만들지 않으면 같은 일이 또 납니다.
