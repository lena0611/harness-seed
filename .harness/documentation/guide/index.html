            파일 흐름으로 보기

            같은 흐름을 파일 관점에서 봅니다. 단계마다 어떤 파일이 읽히고, 어떤 파일 변경이 검사·훅을 깨우고, 어떤 파일이 만들어지거나 갱신되는지를 표시합니다. 위 단계 지도가 "무엇을 하나"라면, 이 그림은 "그때 디스크에서 무슨 일이 일어나나"입니다.

            읽기 단계가 참고만 하는 파일 — 내용이 바뀌지 않습니다 트리거 이 파일·경로의 변경이 검사나 훅을 깨웁니다 쓰기 단계가 만들거나 갱신하는 파일

            ① 일반 작업 — 요청 하나가 흐르는 동안

            항상 읽는 최소 기준은 짧게, 나머지는 이번 작업과 관련된 것만 골라 읽습니다(컨텍스트 합성 프로토콜).

            푸시

            트리거
            • .githooks/pre-push → 기획 연동 gate 프로젝트면 push 정산 게이트
            읽기
            • push되는 커밋 시점의 .harness/spec-sources.json, .harness/spec-lock.json, .harness/project/spec-map.md
            • 매핑된 기획 문서가 미정산이면 차단 — 정산 후 재푸시
            →

            푸시 후 보고

            읽기
            • .harness/project/issue-adapter.md — 파일이 있으면 켜짐
            • 이슈 트래커 읽기 전용 조회 1회 → 한 줄 보고(실패는 실패로)

            ③ 기획 확인 — /기획확인 한 번의 안쪽

            기준 본문(spec-cache)은 팀이 확인 도장을 찍은 시점, 최신 사본(spec-latest)은 지금 기획 저장소에 있는 것. 정산이 그 간격을 닫습니다.

            최신 확인

            harness:spec:fetch -- --cache-only

            읽기
            • 기획 저장소(네트워크, 읽기 전용)
            쓰기
            • .harness/generated/spec-latest/<소스>/ + 기록(manifest)
            • 팀 기준(spec-lock.json)은 불변
            →

            대조

            읽기
            • spec-latest/(최신) ↔ spec-cache/(기준 본문) 비교
            • 내 담당 문서만 코드 영향 판단 — 담당 밖은 전달만
            →

            정산

            harness:spec:settle -- --doc "<경로>"

            읽기
            • 기획 저장소 git 객체 — 읽은 스냅샷 검증(위조·가짜 삭제 거부)
            쓰기
            • .harness/spec-lock.json — 기준 전진(앞으로만)
            →

            팀 공유

            트리거
            • lock 커밋·push → 팀원 pull의 post-merge 훅
            쓰기
            • 팀원 로컬 .harness/generated/spec-cache/ 자동 수화
