# Critical Paths

프로젝트에서 실수 비용이 큰 파일, 디렉터리, 외부 연동 지점을 선언합니다.

하네스는 이 문서의 `path` 값을 읽어 변경 파일과 비교합니다. 매칭되면 `harness:check`에서 더 강한 리뷰와 검증을 안내합니다.

## 선언 표

아래 표는 비어 있는 상태로 시작합니다. **이 프로젝트에서 실제로 위험한 경로**가 생기면 채우세요
(설치 직후 빈 것이 정상입니다 — 예시 경로를 미리 채워 두면 저장소에 없는 유령 선언이 됩니다).

| path | 왜 중요한가 | 권장 검증 |
| --- | --- | --- |

## 작성 방법

- 경로는 백틱으로 감쌉니다. 한 칸에 여러 경로를 두려면 각각 백틱으로: `` `a.js` ``, `` `b.js` ``
- 작성 예시 (참고용 — 아래 블록은 하네스가 읽지 않습니다):

```text
  | path                  | 왜 중요한가                               | 권장 검증            |
  | --------------------- | ----------------------------------------- | -------------------- |
  | src/domain/**         | 도메인 규칙 변경이 사용자 동작에 직접 영향 | 관련 테스트, decision-log |
  | app/billing/**        | 결제·정산 — 실수 비용이 큼                 | 관련 테스트, 수동 확인 |
  | .harness/spec-lock.json | 기획 연동 기준 — 잘못 바뀌면 정산 판정이 틀어짐 (연동 프로젝트만) | spec:status |
```

## 운영 원칙

- 구체적인 프로젝트 핵심 경로가 생기면 이 표에 추가합니다.
- 단순히 파일이 자주 바뀐다는 이유만으로 추가하지 않습니다. 장애, 데이터 손상, 배포 실패, 사용자 주요 흐름에 영향을 줄 때만 critical path로 둡니다.
- 경로가 매칭되면 변경 이유, 검증 결과, 수동 조치 여부를 `decision-log.md` 또는 업무 히스토리에 남깁니다.
