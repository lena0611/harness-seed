## 테스트 전략 선택지
테스트 루트나 `test` script가 없다면 아래 중 하나를 선택해 이 문서 또는 `decision-log.md`에 기록합니다.

1. 초기 단계: lint + build + 수동 확인
2. 단위 테스트: 프로젝트 스택에 맞는 unit test 도구 도입
3. 통합 테스트: API, 저장소, 외부 연동 경계 검증
4. E2E 테스트: 주요 사용자/운영 흐름 검증
5. 테스트 보류: 사유와 재검토 조건을 `decision-log.md`에 기록

## 리포트 이슈 보드 운영 (2026-09-02 사용자 지시)

소비자 설치·업데이트 리포트(라벨 `설치리포트`)의 열림/닫힘은 본체 에이전트가 관리한다.

- **정상 완료 리포트**(개선요청 없음): 내용 확인 후 바로 close — 처리할 것이 없으니 열어둘 이유가 없다.
- **개선요청·결함 포함 리포트**: 수정이 **릴리스로 나간 뒤** close한다. close 전에 처리 내역
  코멘트를 남긴다(반영 버전·커밋·요지 — 소비자가 나중에 봐도 알 수 있게). 반영이 커밋됐지만
  아직 미릴리스면 "반영됨, vX.Y.Z에 실릴 예정" 코멘트만 남기고 열어둔다.
- **소급 기록 이슈**(설치일 원장 등): 등록 즉시 close — 원장은 닫혀 있어도 현황판 재생성이
  state=all로 읽으므로 표에 계속 반영된다.
- **현황판 이슈**(라벨 `설치이력표`)는 상시 open.
