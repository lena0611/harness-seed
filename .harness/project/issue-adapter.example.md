# 이슈 조회 설정 견본 (issue-adapter.example.md)

> **이 파일은 견본입니다. 이 이름 그대로는 아무 일도 일어나지 않습니다.**
> 사용하려면: 이 파일을 복사해 같은 폴더에 `issue-adapter.md`로 저장하고
> 아래 네 칸을 자기 프로젝트 값으로 채우세요. 그 순간부터 에이전트가
> 커밋·푸시 완료 보고에 이슈 요약 한 줄을 덧붙입니다.
> 끄고 싶으면 `issue-adapter.md`를 지우면 됩니다. 하네스에 알릴 필요 없습니다.
>
> 실물(`issue-adapter.md`)은 프로젝트 소유입니다. 하네스는 실물을 배포하지
> 않으므로(배포하면 모든 프로젝트에서 켜지고, 업데이트가 프로젝트 값을 덮습니다)
> 업데이트가 영원히 건드리지 않습니다.

## ① 조회 방법 (필수)

에이전트는 push 완료 후 아래 명령을 그대로 한 번 실행합니다(읽기 전용).
토큰 값은 절대 이 파일에 적지 말고 환경변수 이름만 적으세요.

```bash
curl --silent --header "PRIVATE-TOKEN: $SPEC_ISSUE_TOKEN_RO" "https://git.example.com/api/v4/projects/<프로젝트ID>/issues?labels=%EA%B8%B0%ED%9A%8D%EB%B3%80%EA%B2%BD&state=opened&per_page=50"
```

- 응답은 JSON 배열이며 각 항목의 `iid`(이슈 번호), `title`, `assignees`를 사용합니다.
- 쿼리의 라벨 값은 URL 인코딩해서 보냅니다(위 예시는 `기획변경`의 인코딩).
- 다른 트래커(지라 등)를 쓰는 프로젝트는 이 블록을 자기 트래커의
  "열린 항목 목록" 조회 한 번으로 바꾸면 됩니다. 조건은 하나 —
  읽기 전용 호출 1회로 끝날 것.

## ② 토큰 환경변수 (필수)

| 항목 | 값 |
| --- | --- |
| 환경변수 이름 | `SPEC_ISSUE_TOKEN_RO` |
| 권한 | 읽기 전용을 권장 (이 흐름에서 쓰기는 CI 잡의 몫이며, 에이전트는 조회만 합니다) |

토큰 값은 셸 프로필 대신 **프로젝트 로컬 파일**(gitignore 대상)에 두기를
권장합니다 — OS(맥/윈도우) 공통이고, 셸 프로필과 달리 모든 프로세스에
노출되지 않습니다. ①의 조회 명령 앞에 이런 로더를 붙이면 됩니다:

```bash
[ -f .issue-adapter.env ] && SPEC_ISSUE_TOKEN_RO=$(sed -n 's/^SPEC_ISSUE_TOKEN_RO=//p' .issue-adapter.env | tr -d '\r')
```

- source가 아니라 값만 뽑는 파싱입니다 — 파일 안의 다른 내용이 실행될
  여지가 없고, `tr -d '\r'`가 윈도우 편집기의 줄끝(\r)로 인한 인증 실패를
  막습니다(실측 함정).
- 파일이 없으면 환경변수를 그대로 쓰므로(폴백) 두 방식이 공존합니다.
- `.gitignore`에 파일명을 등록하고, 빌드 도구가 자동으로 읽는 `.env`
  계열과는 다른 이름을 쓰세요.

환경변수가 비어 있거나 호출이 실패하면 에이전트는 요약 대신
"이슈 조회 실패(원인)"라고 적습니다. 이슈 0건과 조회 실패는 다른 말이므로
실패를 조용히 숨기지 않습니다. 커밋·푸시 결과에는 영향이 없습니다.

### 토큰이 없을 때 (처음 설정하는 개발자 안내 — 에이전트용)

조회 실패의 원인이 토큰 미설정이면, 에이전트는 실패 표기와 함께 아래
안내를 보고에 실어줍니다. 새 개발자가 별도 온보딩 문서 없이 그 자리에서
셋업할 수 있게 하기 위함입니다(프로젝트 사정에 맞게 수정하세요):

> 프로젝트 루트에 `.issue-adapter.env` 파일을 만들고 한 줄을 넣으세요:
> `SPEC_ISSUE_TOKEN_RO=<토큰 값>` — 값은 리더에게 DM으로 받습니다.
> 이 파일은 git에 올라가지 않습니다(.gitignore 등록됨).

## ③ 요약 형식 (필수)

조회 결과를 아래 형식의 **한 줄**로 만들어 완료 보고 끝에 덧붙입니다.

```text
열린 기획 이슈 {전체}건 — 미할당 {미할당수} · 담당 지정 {지정수} ({번호 나열, 최대 5개})
```

- 0건이면: `열린 기획 이슈 없음`
- 형식은 프로젝트가 자유롭게 바꿔도 됩니다. 지켜야 할 것은 한 줄일 것,
  실패를 실패로 말할 것 두 가지뿐입니다.

## ④ "내 담당" 구분 (선택)

요약에서 "내 담당 M건"을 구분하고 싶을 때만 채웁니다.
개발자 이름과 트래커 계정의 대응표가 필요합니다.

| 이름 (git user.name) | 트래커 계정 |
| --- | --- |
| 예시이름 | example-id |

- 이 표가 없으면 "내 담당" 구분 없이 전체·미할당만 셉니다. 흐름에는 지장 없습니다.
- 이 표는 CI 잡의 담당자 자동 배정에도 같이 쓸 수 있습니다.

## 에이전트가 지키는 규칙 (하네스 공통 — 프로젝트가 바꿀 수 없음)

- push가 끝난 뒤에만 조회합니다. 커밋·푸시를 막거나 늦추지 않습니다.
- 읽기만 합니다. 이슈를 만들거나 닫거나 코멘트하지 않습니다(이슈를 열고
  닫는 방식은 프로젝트 재량 — 보통 프로젝트 소유 CI 잡의 일입니다).
- 알리고 멈춥니다. 개발자가 이슈 번호를 지목할 때만 처리에 착수합니다.
- 요약은 한 줄입니다. 완료 보고를 점령하지 않습니다.
- 이 동작은 집행 강도(advisory/gate) 판정에 들어가지 않고 영향도 받지 않습니다.
