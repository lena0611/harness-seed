# /연결프로젝트

이 저장소(세션 주 폴더)를 **기준 프로젝트**로 두고 다른 저장소를 "연결"합니다. 연결되면 새 세션 시작 때
그 저장소의 CLAUDE.md·서비스 룰 위치, 하네스 런처 경로, "커밋은 그 저장소 안에서"가 자동으로 안내됩니다.
설정 파일은 사람이 아니라 이 절차가 씁니다 — JSON을 손으로 만들게 하지 마세요.

## 0. 먼저 한 줄로 확인

- 창을 둘 열어 저장소마다 세션을 따로 쓰면 이 연결은 **필요 없습니다**(양쪽 하네스 100%). 한 창에서 둘 다 다루고 싶을 때만 진행합니다.
- 이 세션의 주 폴더가 이 저장소의 **루트**인지 확인합니다(상위 폴더·하위 폴더로 열었으면 훅이 하나도 안 돕니다 — 루트로 다시 열도록 안내).

## 1. 물을 것 세 가지 (인자로 받았으면 생략)

질문 UI(AskUserQuestion)로 한 번에 묻습니다:

1. **어느 저장소인가** — 이 PC에 clone돼 있으면 **폴더 경로**(예: `../common`)가 가장 좋습니다(git 주소는 폴더에서 알아냅니다). clone이 없으면 git 주소.
2. **관심 폴더**(선택) — 그 저장소 안에서 주로 만질 하위 폴더(예: `ss/multisite`). 그 폴더의 CLAUDE.md를 "먼저 읽기"로 지목합니다.
3. **표시 이름**(선택) — 안내에 보일 이름(예: `백엔드`). 생략하면 저장소 이름.

## 2. 실행

```bash
.harness/bin/harness linked add --repo <폴더 경로 또는 git 주소> --focus <관심 폴더> --label <표시 이름>
```

이 명령이 하는 일:
- `.harness/policy/profile.json`의 `linkedProjects`에 `{ label, repo, focus }`를 씁니다(팀 공유 — PC 경로는 적지 않음).
- `.claude/settings.local.json`의 `permissions.additionalDirectories`에 그 폴더를 넣습니다(개인 설정 — 파일 접근 권한 + 하네스가 위치를 찾는 단서).
- 끝에 해석 상태 표를 보여줍니다. 같은 저장소를 다시 실행하면 갱신만 됩니다(중복 없음).

git 주소만 있고 폴더를 못 찾으면 "이 PC에서 폴더를 찾지 못했습니다"가 나옵니다 — clone 위치를 `--dir`로 주면 됩니다.

## 3. 결과 확인

출력의 상태 표에서 두 가지를 봅니다: **위치**가 풀렸는지(`additionalDirectories 의 git remote 일치`), **기준 문서**에 그 저장소 CLAUDE.md(와 관심 폴더 CLAUDE.md)가 잡혔는지. 나중에 다시 보려면 `.harness/bin/harness linked`.

## 4. 사용자에게 알릴 것

- `profile.json` 변경은 **커밋**해야 팀원에게 적용됩니다. `settings.local.json`은 개인 파일이라 **커밋하지 않습니다.**
- 연결 안내는 **새 세션부터** 붙습니다.
- 연결된 저장소의 Claude 세션 훅은 이 창에서 돌지 않습니다. 그 팀 전용 규칙은 문서(`domain-rules.md`·관심 폴더 CLAUDE.md)에, 물리 검사는 그 저장소의 git pre-commit에 두는 것이 정본입니다 — `.harness/policy/context-protocol.md` "연결 프로젝트".

## 5. 기록

연결 선언은 팀 결정이므로 `.harness/session/decision-log.md`에 한 줄 남깁니다(무엇을 왜 연결했는지).
