# /기획확인

**절차 정본은 `.harness/project/spec-authority-workflow.md` 4절입니다.** 이 파일은 Claude Code 진입점(어댑터)이며, **팀원의 "내 몫 확인" 범위만** 다룹니다.

저장소 전체 기준을 움직이는 일 — 최초 연동, 새 문서 편입, 기준 통째 이동(`--move-baseline`), 매핑 신설 — 은 이 명령의 범위 밖입니다. 그런 요청이 오면 진행하지 말고 개발리더의 `/기획문서연동`으로 안내합니다.

인자: `$ARGUMENTS` — 문서 경로가 오면 그 문서만 다룹니다.

## 순서

1. `npm run harness:spec:fetch -- --cache-only`로 최신을 확인합니다. 팀 기준(lock)은 움직이지 않습니다.
2. `npm run harness:spec:status`로 미확인 변경을 봅니다. 없으면 "확인할 변경이 없습니다" 한 줄로 끝냅니다.
3. **내 담당 변경**(내 코드에 매핑됐거나 이번 작업에 걸린 문서)마다:
   - 최신 본문(`.harness/generated/spec-latest/`)과 기준 본문을 대조해 **무엇이 바뀌었는지** 보여줍니다.
   - 코드 영향을 함께 판단합니다. 반영이 필요하면 작업 계획으로 보고하고(구현은 승인 후), 영향이 없으면 근거를 `decision-log.md`에 남깁니다.
   - 개발자가 확인을 마친 문서만 `npm run harness:spec:settle -- --doc <경로>`로 기록합니다. **정산은 자기 몫만** — 남의 영역 문서를 대신 기록하지 않습니다.
4. **담당 밖 변경**은 판정하지 않습니다. 목록만 보여주고 담당자에게 전달하도록 안내합니다.
5. 마지막에 반드시 안내합니다: **`spec-lock.json` 변경이 커밋·push까지 되어야** 팀 기준에 반영되고, 채널 알림(CI 백스톱)이 멈춥니다. 브랜치에만 있는 확인 기록은 팀 입장에서는 아직 없는 기록입니다.

## 결과 보고

- 확인한 문서와 판단 (반영 예정 / 영향 없음 + 근거)
- 기록을 남긴 문서 목록
- 담당 밖이라 전달만 안내한 목록
