# /검증설정

**계약 정본은 `.harness/project/config-contract.md`의 verify 절입니다.** 이 파일은 Claude Code 진입점(어댑터)입니다.

기본값 이해가 먼저입니다: **하네스는 package.json에 lint/test/build 스크립트가 있어도 자동으로 실행하지 않습니다**(결정 86). 이 명령은 그 실행 주체를 개발자와의 문답으로 정하고, 답을 `.harness/policy/profile.json`의 `verify` 필드에 기록하는 절차입니다.

## 순서

1. **현재 상태를 먼저 보여줍니다** (질문 전에 사실부터):
   - `package.json` scripts 중 `lint` / `test` / `build` 유무
   - `.harness/policy/profile.json`의 현재 `verify` 선언
   - 외부 훅 도구 흔적: `.husky/` 디렉터리, package.json의 `lint-staged`·`prepare` 체인
   - 적용 스택 manifest의 raw `verify` 선언 유무
2. **감지된 단계마다 하나씩 묻습니다** (한 번에 한 질문, 선택지 제시):
   > **lint는 누가 돌릴까요?**
   > ① 하네스가 커밋 때 실행 (`"harness"`)
   > ② husky 등 프로젝트 도구가 담당 — 하네스는 위임 표기만 (`"external"`)
   > ③ 지금은 아무도 안 돌림 (미선언 유지)
   - husky/lint-staged가 감지된 프로젝트에는 ②를 권장으로 표시하고 이유(커밋 파일만 검사 vs 전체 검사, 이중 실행 방지)를 한 줄로 덧붙입니다.
   - 스크립트가 없는 단계는 묻지 않습니다. `"harness"`를 원하는데 스크립트가 없으면 스크립트부터 필요하다고 알립니다.
3. **답을 받아 에이전트가 `profile.json`을 채웁니다**: `verify` 필드만 수정하고 다른 필드는 건드리지 않습니다. ③(미선언)을 고른 단계는 필드에서 제거합니다.
4. **결과를 표로 보고합니다**: 단계별 담당자와 실제 거동(커밋 때 무엇이 돌고 무엇이 안 도는지).
5. **커밋 안내로 마칩니다**: profile.json은 커밋되는 팀 공유 설정입니다 — **커밋·push까지 되어야** 팀원 전체와 모든 에이전트에 적용됩니다. 커밋은 사용자 승인 후 진행합니다.

## 기준

- 값 도메인은 `"harness"` / `"external"` 둘뿐입니다. 그 외 값은 실행되지 않고 경고만 나옵니다(오타가 조용히 옵트인되지 않음).
- `"external"`은 스택 raw verify까지 건너뜁니다 — 프로젝트 선언이 스택 기준을 이깁니다.
- 이 명령은 husky·lint-staged 설정 자체를 만들거나 고치지 않습니다. 그쪽이 필요하면 `.harness/project/hook-coexistence.md`를 안내합니다.
- 팀 결정이 필요해 보이면(담당자 의견 갈림) 즉석 기록 대신 `.harness/session/developer-input-queue.md`에 질문을 남깁니다.
