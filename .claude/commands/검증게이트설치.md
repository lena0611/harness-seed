# /검증게이트설치

하네스는 코드 품질 검사(lint/테스트/빌드)를 실행하지 않습니다 — 소유는 프로젝트입니다(결정 92).
이 명령은 그 소유권을 전제로, **요청받았을 때만** 올바른 구성을 대신 설치해 주는 도우미입니다.

## 정신 (설치 전후로 반드시 지킬 것)

1. **부르지 않으면 아무것도 하지 않는다** — 이 명령 밖에서 감지·설치·수정하지 않습니다.
2. **설치물은 100% 프로젝트 소유다** — husky·lint-staged 설정은 프로젝트 것이며, 하네스는 이후 갱신·검사·관여하지 않습니다.
3. **하네스를 제거해도 살아남아야 한다** — 설치 결과가 하네스 파일에 의존하지 않게 합니다(훅 공존 배선 한 줄 제외).

## 견본 출처 (정본 — 결정 96)

`https://git.smartscore.kr/ai-standard/toolkits/quality-gates` — 검증 게이트 견본·설정법의
**회사 정본**입니다. 사람이 직접 설치할 때도, 에이전트가 대리 설치할 때도 같은 정본을 따릅니다.

- 견본·설정을 기억이나 다른 프로젝트에서 지어내지 않습니다. 반드시 이 저장소를
  clone(최신 태그)해 가져옵니다.
- 저장소 구조: `stacks/<스택>/`에 스택별 실물(recipes.md·presets/·ci/),
  `principles/`에 스택 무관 판단 기준(로컬 훅 vs CI, 하네스 훅 공존).
  **먼저 프로젝트의 스택을 판정하고 그 폴더만 봅니다** — 예: Node 프로젝트면
  `stacks/node/`. 해당 스택 폴더가 비어 있으면 아래 "없는 유형" 절차를 따릅니다.
- 프로젝트 사정에 맞춘 조정은 프리셋·레시피가 안내하는 범위에서 합니다
  (없는 도구 줄 삭제, pre-push 조합 선택 등).
- 저장소에 없는 유형·조합이면 사용자에게 알리고 만들어 쓰되, 범용성이 있으면
  저장소 MR 역제안을 안내합니다 — 정본은 그렇게 자랍니다.
- 예외: 하네스 깃훅 공존 배선은 `.harness/project/hook-coexistence.md`가 정본입니다.

## 순서

1. **현황 파악**: package.json의 lint/test/build 스크립트 유무, husky·lint-staged 설치 여부,
   `.husky/` 상태, 기존 `prepare`/`postprepare` 값, lint 설정 파일(.lintstagedrc*, eslint, prettier, oxlint).
2. **문답**: 무엇을 언제 돌릴지 확인합니다 — 기본 권장: 커밋 때 스테이징 파일 lint,
   push 때 테스트(선택), 빌드는 CI. 이미 있는 구성은 파괴하지 않고 보완만 합니다.
3. **조달**: 툴킷 저장소를 임시 디렉터리에 clone(태그 우선)하고 맞는 프리셋을 가져옵니다.
   프로젝트에 없는 도구의 줄(oxlint 등)은 프리셋 README 지침대로 빼고 조정합니다.
4. **하네스 제외 규칙(필수)**: 하네스 프로젝트면 `.prettierignore`/oxlint/eslint에
   `.harness/**` 제외가 있는지 확인하고 없으면 넣습니다 — 빠지면 lint가 하네스 파일을
   고쳐 업데이트가 영구 동결됩니다(0.2.109 실측 사고).
5. **훅 공존 배선**: 하네스 깃훅을 쓰는 프로젝트면 `prepare: "husky"` +
   `postprepare: "node .harness/bin/install-hooks.mjs"` 표준 배선을 답니다
   (정본: `.harness/project/hook-coexistence.md`). husky를 훅 주인으로 두고 하네스가
   husky를 체인하는 역방향 구성은 순환이므로 만들지 않습니다.
6. **검증**: 더미 변경으로 커밋을 시도해 검사가 실제로 도는지 확인하고 결과를 보고합니다.
   (커밋은 확인 후 되돌리거나, 사용자 승인 하에 남깁니다.)
7. **소유권 고지**: "설치된 설정은 프로젝트 소유이며 자유롭게 수정 가능, 하네스는 관여하지 않음"을
   보고에 명시합니다.

## 기록

- 설치 결과(무엇을 어디에, 어떤 조정을 했는지)를 `.harness/session/decision-log.md`가 아니라
  커밋 메시지와 보고로 남깁니다 — 프로젝트 소유물이므로 하네스 결정 로그 대상이 아닙니다.
