# /기획문서연동

**절차 정본은 `.harness/project/spec-authority-workflow.md` 입니다.** 이 파일은 Claude Code 진입점(어댑터)이며, 별도 규칙을 두지 않습니다. Codex·Copilot도 같은 정본을 읽습니다.

먼저 정본을 읽고 그대로 수행합니다. 정본 맨 앞에 용어 대조표(기준 시점=우리가 본 기획 버전, 수화=본문 받아오기, 정산=확인 완료 표시)가 있으니, 개발자에게 설명할 때는 그 쉬운 말을 씁니다.

인자: `$ARGUMENTS` — 저장소 주소가 함께 오면(예: `/기획문서연동 https://...git`) 질문 없이 그 주소로 최초 연결(정본 2절)을 진행합니다.

## 이 명령을 받았을 때 순서

1. `.harness/project/spec-authority-workflow.md`를 읽습니다.
2. `npm run harness:spec:status`로 현재 상태를 확인합니다.
3. **연동이 없으면** → 정본 2절(최초 연결). 인자로 주소를 받지 않았다면 **다른 설명 없이 곧바로 묻습니다** — 이 명령의 첫 응답은 질문이어야 합니다:

   > 이 프로젝트의 요구사항을 관리하는 Git 저장소가 있나요? 있다면 주소를 알려주세요.

   주소를 추측하거나 후보를 제시하지 않습니다.
4. **이미 연동돼 있으면** → 정본 4절(업데이트 흐름).
5. 매핑은 정본 3절대로 근거와 함께 제안하고, 개발자가 확인한 것만 기록합니다.

## 결과 보고

- 연결한 저장소와 기준 commit
- 기획 문서 N건 중 매핑 M건, 미매핑 목록
- 매핑 없는 기능 코드 영역(있으면)
- 개발자 확인이 필요해 보류한 항목

**프로젝트 헌장이 아직 TBD라면** 마지막에 제안합니다: 기획 문서를 근거로 헌장 초안(문제·사용자·비목표·성공 기준)을 만들 수 있다고 안내하고, 원하면 `bootstrap.md`의 인터뷰 절차로 진행합니다. **이미 채워진 헌장은 건드리지 않습니다.**

## CI 백스톱 (선택)

push 훅이 못 보는 것 — 서버에서 일어나는 MR 머지, 아직 아무 코드에도 매핑되지 않은 신규 기획 문서 — 는 스케줄 CI가 맡습니다.

```yaml
# .gitlab-ci.yml — 스케줄 파이프라인(예: 매일 아침)
spec-freshness:
  rules:
    - if: '$CI_PIPELINE_SOURCE == "schedule"'
  script:
    - npm ci
    - npm run harness:spec:fetch -- --cache-only
    - npm run harness:spec:status | tee spec-status.txt
    - if grep -q "감지된 변화" spec-status.txt; then
        curl -s -X POST -H 'Content-Type: application/json'
          -d "{\"text\":\"[기획문서연동] 미정산 기획 변경이 있습니다.\n$(grep -A20 '감지된 변화' spec-status.txt | head -15)\"}"
          "$MATTERMOST_WEBHOOK_URL";
      fi
  allow_failure: true
```

CI 워크스페이스는 버려지므로 이 잡이 캐시를 갱신해도 팀 기준에는 영향이 없습니다.
